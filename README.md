# 🕵️ Conspiracy Radar

**An explainable NLP tool that detects conspiracy-style rhetorical patterns in text** — not by keyword spam, but by identifying the actual linguistic structures (hidden-agent framing, us-vs-them language, false certainty, missing sourcing, emotional urgency) that misinformation research associates with conspiratorial rhetoric.

## Why this project

Most beginner NLP projects are sentiment classifiers on movie reviews. This one asks a more interesting question: **can we detect *how* something is being argued, independent of whether it's true?** A claim can be factually correct and still use manipulative rhetoric, or false and sound perfectly calm. Separating rhetorical style from truth value is a genuinely useful, underexplored angle — and it builds directly on prior NLP research work I've done (emotion recognition in text).

## How it works

The tool blends two layers:

1. **Rule-based linguistic pattern detector** — regex-driven matching across 5 rhetorical categories (hidden-agent framing, us-vs-them framing, false certainty, missing/vague sourcing, emotional urgency). This layer is fully explainable: it shows you *exactly* which phrases triggered a flag.
2. **Statistical classifier** — a TF-IDF + Logistic Regression model trained on a labeled starter dataset of conspiracy-style vs. neutral text, catching patterns the rules miss.

The final score is a weighted blend of both, so the tool isn't a black box — every score comes with a visible "why."

```
Text input → [Rule-based pattern scan] → category breakdown
           → [TF-IDF + Logistic Regression] → statistical score
           → weighted blend → final score + explanation
```

## Limitations & future work

- The starter dataset (52 examples) is small and hand-curated — accuracy will improve significantly with a larger, more diverse labeled dataset (this is intentionally left as an extension point).
- The tool scores *rhetorical style*, not factual truth. It should never be used as a standalone fact-checker.
- Planned improvements: expand the dataset across more topics/languages, add a browser extension front-end, experiment with transformer-based embeddings instead of TF-IDF.
